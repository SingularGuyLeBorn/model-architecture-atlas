# React Flow 与自适应布局

## 三层结构

组件分三层，禁止把语义、坐标和 JSX 混在同一个巨大 `buildGraph` 中：

1. **语义图**：节点 id、角色、公式、维度、父子关系和边端口。
2. **测量与布局**：根据 DOM 实际尺寸和层级关系计算坐标、通道和整体边界。
3. **渲染**：数据框、运算节点、分组容器和边只消费布局结果。

内容变化后必须重新测量和布局，不能靠增大一个固定高度数字“顶开”。

## 内部小框端口

可连接的小框拥有稳定端口 id，例如：

```tsx
<TensorSlice
  id="q-1"
  tex="Q_1"
  sourcePort="q-1-out"
/>
```

端口可以位于自定义 React Flow 节点的后代元素。边通过 `sourceHandle`、`targetHandle` 指向具体小框；外层分组容器不提供替代性总端口。

内部布局变化后调用 React Flow 的节点内部更新能力，让 handle 坐标与 DOM 保持一致。

## 自适应尺寸

- 节点宽高以内容实测值为准；可以设置设计上的最小值，不能设置为了容纳当前文本而猜出的固定高度。
- 使用 CSS Grid/Flex 分配模块区域，配合 `min-width:0` 和合理换行；`minmax(0,1fr)` 只用于确实需要分配剩余空间的轨道，不能让内部元素格跟着等分拉宽，也不能用 `overflow:hidden` 掩盖裁切。
- 布局完成后从全部节点实际边界计算 graph bounds，再加统一画布 padding。
- 宿主高度由 graph bounds 推导。若 Markdown/iframe 仍要求固定 `aspect`，应从 registry 尺寸自动读取或增加尺寸上报；禁止在文章、registry、组件三个位置手工同步高度。
- `fitView` 只负责缩放，不能用来掩盖错误节点尺寸。

推荐流程：初始渲染 → 测量节点 → 分层布局 → 更新节点和 graph bounds → 宿主同步高度。测量完成前使用稳定占位，避免画布跳动。

### 元素框按内容定宽

- **从内容决定元素框尺寸，不从父框宽度倒推。** 标量、单个元素和短表达式只占文字及必要内边距；不能因父框较宽就使用 `width:100%`、`flex:1` 或等分轨道撑满。张量维度写在角落，维度大不代表单个元素框要大。
- 元素框优先采用内容宽度（如 `max-content`、`fit-content`），用对齐和间距组织成组。矩阵同列、同类操作数可按本组最长标签统一宽度，既保留行列规律，也容纳多位上下标；不要把某个截图的像素宽度定成所有元素的通用尺寸。
- 区分元素格、向量与矩阵容器。向量需要容纳代表元素，矩阵需要对齐行列，不能全部压成标量小框；同样不能让一个标量继承旁边矩阵的宽度。并排区域可以等宽，区域内部对象不必铺满。
- 小框收紧后，若父框仍有大片空白，要一起重排父级：独立分支横向并排；串行阶段可用向右箭头连接，过长时分行并保留明确的跨行连接。不能只在巨大空框中摆几个小格，也不能用无关内容填空。
- 收紧过程中保留字号、代表元素、完整变量名和端口净空，不靠缩字、隐藏溢出或删结构达标。尺寸变化后按实际边界重算连线，箭头仍须接到对应小框。
- 验收同时看外框和框内留白：在相同字号与缩放下加宽父容器，内容未变的元素格不应随之等比例膨胀；再换成最长索引与标签，确认文字完整、行列对齐且连线不穿框。没有溢出不等于紧凑，必须截图检查元素文字两侧是否仍有无意义的长条空白。

### 框体间距与环形排列

同级框体的实际矩形不得相交，内部元素格、缓存槽位和中心标签也要检查；父子包含关系单独处理。框间保留可见净空，检查对象包括边框、文字和尺寸变化后的边界。

环形布局按卡片矩形验收，而非只看圆心或圆周。例如直径 240、半径 81.6 的圆上放 8 个 72×28 槽位，顶部与斜上槽位的中心纵距只有约 23.9，小于卡片高度，卡片会重叠。可按空间增大半径或收紧卡片尺寸；当前示例采用半径 87.6、约 63.6×21.6 的卡片，最近纵向净空约 4。中心写入标记和底部标题也须避让。省略号只显示符号，不铺背景或伪装成槽位。

浏览器验收时两两比较同级元素的 `getBoundingClientRect()`，横向和纵向的重叠长度都大于 0 即失败；额外核对文字是否越出自身卡片。正常阅读宽度、窄屏和有两位数层号的模式都要截图检查，不能靠提升层级或隐藏裁切遮住重叠。

## 模块解释面板

本项目的结构图与文字解释并存，面板不能替代图中的结构展开。

- 首次点击模块打开右侧面板；面板已打开时，点击其他模块只更新内容，保持打开，直到用户手动关闭。关闭后继续点击模块只改变选择，不自动重开；只有用户点击“展示解释”才重新打开。将“选中对象”与“面板是否允许显示”分别管理，不能用选中对象变化强制开面板。
- 内容针对当前模块和当前模型、层号、Prefill/Decode 状态，写清模块作用、每个变量的定义与形状、输入来源、内部步骤、公式推导、输出去向和必要的数值例子；不能只换标题或复述图上的缩写。
- 面板与画布分配独立空间，不能覆盖刚点击的框。打开或调整宽度后，确保目标框仍在画布可见区域内，必要时最小幅度平移；不能靠把整图缩到字看不清来避让。窄屏也须保留图文对照，不能直接用遮盖目标的浮层交差。
- 外观简洁、素雅，标题与正文层级清楚，滚动阅读稳定。面板内滚轮只滚动文字，不带动画布；拖动框、连线或画布不能被误判为点击打开面板。
- 验收完整序列：点击 A 打开 → 点击 B 保持打开并换内容 → 手动关闭 → 点击 C 仍关闭 → 点击“展示解释”显示 C；另检查面板打开时目标框不被遮挡。

## 画布外观与阅读

- 本项目采用用户提出的透明大框试验样式：分组大框保留外轮廓，内部背景与画布一致，不铺整片白底；数据小框继续保留语义色。此项是项目样式选择，不要求所有模型图都透明。检查嵌套边界、文字对比度及底层连线，透明不等于允许线穿过文字。
- 变量在框内，维度放标题角落，不采用“第一行一个变量、第二行一个维度”的高大空框。正文与变量在常用阅读尺度下可读，不以反复放大作为正常阅读前提。
- 连线标签按用户要求至少比普通说明字大三个字号档位，使用明确的字号 token 并在同一缩放下比较；本项目现用 20px 与 13px 作为基准。长线箭头端重复变量名；保持透明背景并让线避开字，不靠白底遮线。
- 选择只高亮原有边框，不叠第二层错位框；无关蓝色端口框、缩放点不能常驻。颜色扩展按语义进行，保持同对象在生成端、代理和消费端一致。

## 持续可编辑交互

- 结构图内部无需设置阅读/编辑开关：空白区域拖动用于平移，节点拖动用于改位置；无需选中即可拖动完整边缘调整尺寸，选中只突出原边框，不叠加第二个框或八个控制点。端口和边始终可操作。连接端口默认透明并保留命中区，悬停达到延迟后才显示 `+`；连接与重连半径应允许端点靠近后吸附。
- 固定起线点与已连接端点优先响应连线，其余边缘响应缩放，不能让两种操作争抢同一事件。连接点沿边界的 20%、40%、60%、80% 等位置分布。连接点默认完全隐藏，指针停留 0.5 秒后才显示圆形 `+`，移开立即隐藏。
- 新建线只从固定起线点发起；点击 `+` 可锁定起点，拖动时开放式箭头跟随指针。目标采用连续边缘吸附：指针进入任意框边的吸附范围后，松开鼠标就连接，不要求再次点击或命中离散 handle。
- 既有边的两端可按住拖动，沿原边滑动时固定法向位置，只改变边上比例；也允许重连其他框。端点存储为节点 id、边方向和归一化比例，不能存绝对屏幕坐标。历史、保存、恢复均包含该数据。
- 端口中心与可见框边重合，路径端点按实际节点边界计算，不能取大号 handle 命中区的外沿。普通端口和未选中边的端点只在局部 hover 时显示；选中边显示两个端点，线段拖动点仅显示鼠标附近的一个。
- 所有主流程边显式指定 sourceHandle/targetHandle，匿名主端口改为稳定 id；新增连线端口不得通过“第一个 handle”冒充主流程出口。浏览器应直接测量路径首尾与节点边界的间隙。
- 四条完整边缘始终保留透明缩放命中带，鼠标靠近即可显示缩放光标并直接拖动，不要求先选中节点。四角控制宽高，四边控制单轴；选中框不显示八个点，角落提示仅局部 hover 时出现。起线点、连线端点与缩放命中区重叠时优先连线，其余边缘均可缩放。
- 有独立语义且需要人工调整的内部对象使用嵌套 child node；父节点先于子节点注册，子节点位置相对父节点保存，并允许直接连接到其他父框内部的真实 handle。
- 文章宿主是否处于编辑状态，不改变结构图自身的交互规则；两者不得共用同一个 `editing` 状态。
- 连线必须从真实 source handle 拖到真实 target handle。删除连接以边为单位，不能连带删除语义节点。
- 人工位置、尺寸和连接可保存为独立布局覆盖层；自动语义图仍是可恢复的底稿。保存失败必须可见，不得悄悄丢失用户调整。
- 布局覆盖层同时保存连线端点、LaTeX 标签和人工折线控制点。基础语义边重连后不能在恢复时被默认端点覆盖。
- 调整尺寸后重新计算端口与边路径；不能只改变外框而让内部端口停在旧位置。
- 画布同时支持空白处拖动与普通滚轮上下平移；缩放保留明确的独立手势或控件，不能把普通滚轮固定为缩放。面板和其他可滚动控件内的滚轮不传给画布。

## 交互性能验收

本项目用户目标是可见反馈不超过 30ms。分别测量整画布平移、单框拖动、滚轮平移、缩放、切层、解释面板首次打开与切换；单框顺畅不能证明整画布顺畅，缩放顺畅也不能证明切层达标。

- 在生产构建、最复杂完整层及面板打开场景实测，记录环境、图规模、首次与重复操作的耗时、P95 和长帧。区分事件处理耗时、下一次可见绘制和完整内容就绪时间，不能只用处理函数执行时间宣称 30ms 达标。
- 平移与缩放不改变图语义，不应逐帧重建全部节点、重排整图或重新渲染全部公式；静态内容与视口变换分离。切层缓存和按需渲染不能留下旧层变量、错位端口或隐藏用户要求的结构。
- 用真实连续拖动、滚轮和连续切层验证，不只测一次点击。截图验收与性能验收都通过才可声明完成；未达标时报告实际测得的路径与指标，不能用“感觉丝滑”或单测绿替代。

## 边路由

- 默认使用分层正交路由，同层对应端口尽量垂直对齐。
- 选中边后只在鼠标靠近的正交线段显示局部拖动控制，不把每段控制点同时铺开；拖动水平段只改变该段的纵坐标，拖动竖直段只改变该段的横坐标。端点另用 reconnect 控制拖到新端口，不能把“改路径”和“改连接对象”混成同一种操作。
- 一条边只由一个边组件绘制，不用多个短 `div` 拼折线。
- 自动折线先对除起点、终点及其父容器之外的节点矩形做避障，再在候选正交通道中选择“穿框数最少、长度最短”的路径；人工控制点存在后不再擅自改路。
- 自动路由必须使用全图统一的节点外扩安全区与端口法向引出长度。候选通道按外扩后的矩形计算，横向或纵向转折不得落在框边及其安全区内；这是路由器不变量，不为某一条边写坐标特例。
- 箭头属于终点，线段连续到箭头基部；不能出现孤立小线头。
- 使用开放式 `Arrow` marker，不使用填充的 `ArrowClosed`。路由起点先沿 source handle 法向离开节点，终点前再加入与 target handle 法向一致的短引入段：Top 向下、Bottom 向上、Left 向右、Right 向左。不能让线贴着源框边横走，也不能让箭头横着贴到目标上边缘。扇出边使用分开的具名 source handle，使每条边的来源可辨认。
- 给主路、残差、路由和共享旁路预留不同通道。跨多个分组的线沿容器外侧走，不穿过公式和节点。
- 边标签的中心始终在线路上；拖动时投影到最近线段，并将位置存为沿路径总长度的比例。节点移动、重连或折线改变后按新路径还原；拖标签一次只记一条历史。标签不能自由漂到线外，也不能看起来像新节点。
- 长边在箭头附近再次标出传递变量；字号按“画布外观与阅读”要求。标签背景保持透明，路径在标签区域断开避让，不能让线穿字，也不能用白底盖住问题。
- 线密度太高时，优先使用合法输入代理或分层总线；不能把不同语义的多条边合成一条无法追踪的线。

### 距离与通道硬约束

- 相邻层之间的净空必须容纳：源 handle、箭头、目标 handle，以及至少一次正交转折。若路由器的 offset 为 `o`，层间净空不得小于 `2o + 箭头长度 + 安全边距`。
- 横向并列的节点之间要留下专用竖向通道。需要跨越下一层的边先进入通道，再向目标转折；不得从相邻节点内部“穿过去”。
- 同一阶段的并行节点尽量让相关 source/target handle 对齐。若无法对齐，转折放在两层之间的空白带，而不是贴着节点边缘回头。安全区必须同时作用于碰撞检测、候选通道和起终点引出段；只给碰撞矩形加 padding、却仍让转折线贴边，仍算失败。
- 长残差必须是一条连续、有箭头的真实边，从原始状态节点直达加法器。不能用颜色相同的短线暗示连接。
- 编辑历史以完整交互为边界：拖动开始前留快照，松手后提交；逐像素变化不得逐条入栈。节点、尺寸、边端点、折线控制点和标签共用同一撤销/重做栈。
- 小框是实际数据源或目标时，handle 放在小框上；禁止把线先接外层大框，再让读者猜它对应哪个内部向量。

布局后必须执行边—节点碰撞检查：沿每条路径采样，排除它自己的 source/target 后，任何采样点进入其他节点内部都算失败。只凭截图肉眼判断不够。

自动布线必须统一规划，而非每条线独立取最短路。手动路径先预留，自动路径逐条预留已占用线段；平行长段须保持通道间距，并检查两两共线重叠。候选通道应覆盖起点、中点和终点附近，不能只保留中点附近候选而丢失起点旁的窄通道。扇出区净空按“源引出段 + 目标引入段 + (分支数 − 1) × 通道间距 + 安全余量”计算，保证各路有空间转折。

## 运算节点

至少区分：

- `BinaryOperator`：多个输入、一个输出，用于 `+`、`\times`、`\odot`。
- `NamedOperator`：Softmax、Top-K、RMSNorm、Concat 等命名操作。
- `TensorBox`、`VectorBox`、`ScalarCell`：只表示数据，不承担运算语义。
- `GroupFrame`：只分组，不代替内部节点接线。

乘号可以位于两条输入线的交点，或使用小型无底色运算节点；不能使用与张量框同尺寸、同视觉权重的矩形。

加法与多项累加统一使用圆形 Σ 节点：各操作数分别有输入线进入圆边，输出线离开圆边后接结果。节点必须保持圆形，不能随 SVG 非等比拉伸成椭圆。若操作数距离较远，在线旁或输入端保留变量名；“逐元素求和”可写在旁边，但不能替代连接结构。

每条已展示输入线都带朝向 Σ 的箭头，并分配圆周上彼此分开的落点；不能全部挤到同一点，也不能只有输出有箭头。输入过多时调整圆与分支间距，不把同构省略项画成 `+ … +` 或无来源短线。

同一分组内的独立分支使用同一行 Grid/Flex，不用自动换行把并行过程排成上下步骤。纵向产品列表汇入求和器时，每个产品行都必须接线，不能只让最后一行向下指向 Σ。内部连接可由组件级 SVG 绘制，不必为每个元素注册 React Flow 节点；坐标由同一布局网格或实测边界推导，检查端点和框边贴合。

## LaTeX 渲染

- 公式只通过统一的 KaTeX/LaTeX 组件渲染，不把 TeX 命令当普通字符串显示。
- JSX 静态字符串与 JavaScript 模板字符串的反斜杠规则不同，修改后必须在浏览器核对；页面出现 `times`、`text`、`operatorname`、`boldsymbol` 等裸命令即为失败。
- JSX 静态属性不是 JavaScript 字符串转义：源码写 `tex="\ldots"`、`shape="N\times512"`。只有花括号内的 JavaScript 字符串或模板字符串才写 `"\\ldots"`、`"\\mathbb"`、`"\\times"`。把两种语境混用会在页面出现 `cdots`、`times512`、`operatorname` 等裸文本。验收不能只数 `.katex-error`，还必须扫描页面可见文本。
- 长公式优先拆成多个有数据语义的小框和运算关系，不能靠缩小字号、强制换行或 `overflow:hidden` 塞进一个框。
- 多位上下标使用花括号；矩阵维度、函数名和转置写法在全图保持一致。

## 自动验收

在最复杂模式和至少一个窄屏宽度运行浏览器检查：

1. 比较每个节点的 `scrollWidth/clientWidth`、`scrollHeight/clientHeight`；任何正溢出都失败。
2. 检查所有边都有存在的 source、target、sourceHandle、targetHandle；控制台出现 handle error 即失败。
3. `.katex-error` 数量必须为 0。
4. 扫描可见公式文本；不得出现未渲染的 TeX 命令名。
5. 对每条边做路径采样，确认不与无关节点内部相交；最复杂层和复用层都要检查。
6. 截取最复杂区域，人工确认内部最后一个小框没有被父容器裁切；只检查外层 scroll 尺寸不够。
7. 核对边数量与语义图。例如展示 3 个 head，就应有 9 条 `Q/K/V` 输入边，不能只有 3 条外层总线。
8. 对正常阅读宽度和窄屏分别验收；缩小 viewport 后不能靠整体缩放把错误藏起来。
9. 改变一个标签长度、专家数或 head 展示数，画布高度应自动变化，不需要修改 registry 或 Markdown 常量。
10. 按“模块解释面板”的完整开关序列检查状态、内容与避让，按“交互性能验收”记录实测数据；没有实际浏览器测量时不得声明交互已达标。
