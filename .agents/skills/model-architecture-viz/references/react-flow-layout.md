# React Flow 与自适应布局

## 三层结构

组件分三层，禁止把语义、坐标和 JSX 混在同一个巨大 `buildGraph` 中：

1. **语义图**：节点 id、角色、公式、维度、父子关系和边端口。
2. **测量与布局**：根据 DOM 实际尺寸和层级关系计算坐标、通道和整体边界。
3. **渲染**：数据框、运算节点、分组容器和边只消费布局结果。

内容变化后必须重新测量和布局，不能靠增大一个固定高度数字“顶开”。

## 内部小框端口

可连接的小框拥有稳定端口 id，例如：

```tsx
<TensorSlice
  id="q-1"
  tex="Q_1"
  sourcePort="q-1-out"
/>
```

端口可以位于自定义 React Flow 节点的后代元素。边通过 `sourceHandle`、`targetHandle` 指向具体小框；外层分组容器不提供替代性总端口。

内部布局变化后调用 React Flow 的节点内部更新能力，让 handle 坐标与 DOM 保持一致。

## 自适应尺寸

- 节点宽高以内容实测值为准；可以设置设计上的最小值，不能设置为了容纳当前文本而猜出的固定高度。
- 使用 CSS Grid/Flex 分配模块区域，配合 `min-width:0` 和合理换行；`minmax(0,1fr)` 只用于确实需要分配剩余空间的轨道，不能让内部元素格跟着等分拉宽，也不能用 `overflow:hidden` 掩盖裁切。
- 布局完成后从全部节点实际边界计算 graph bounds，再加统一画布 padding。
- 宿主高度由 graph bounds 推导。若 Markdown/iframe 仍要求固定 `aspect`，应从 registry 尺寸自动读取或增加尺寸上报；禁止在文章、registry、组件三个位置手工同步高度。
- `fitView` 只负责缩放，不能用来掩盖错误节点尺寸。
- 标题优先保持单行，去除重复修饰或把次要说明放旁注，保留模块名、维度与必要索引。标题字体、宽度变化后，正文按自然高度排版，子框实测高度参与父框及下游位置计算；不能保留旧固定高度，让第二行标题挤掉公式。检查标题行数、正文实际边界、子框包含关系及宽高双向溢出，不只比较外框宽度。人工收窄后的合法换行也必须完整撑开内容。

**错误案例：** Head 标题字号加大，但子框仍为旧的 64px 高；“Head 64 · 元素 32257–32768”换行后公式越出底边。另一参数框把“列向量”的最后一个字挤到下一行。应精简重复标题、按真实内容定高，再从子框边界推导分组高度，不能缩字或隐藏溢出。

推荐流程：初始渲染 → 测量节点 → 分层布局 → 更新节点和 graph bounds → 宿主同步高度。测量完成前使用稳定占位，避免画布跳动。

### 元素框按内容定宽

同样约束高度：单行符号框的高度取真实公式高度（含上下标）加上下必要内边距与边框，不用大额纵向 padding、固定高、`align-items:stretch` 或 `1fr` 行轨道拉高。只含 `w₁` 的参数列标签保持紧凑；只有真正展开多个列元素时才形成竖向列框。收紧后同时收紧外层矩阵与运算行，并重新测量端口。

**高度错误案例：** 参数矩阵只展示 `w₁、w₂、…、w₂₄`，每个单符号却套进高柱，或以 20480×24 的形状为理由模拟矩阵比例。维度用标注表达；单符号格按字高加内边距，实际列组成需要展示时才展开代表元素。验收同时改变父框宽和高，确认内容不变的小框不会跟着膨胀，并截图检查上下空白。

- **从内容决定元素框尺寸，不从父框宽度倒推。** 标量、单个元素和短表达式只占文字及必要内边距；不能因父框较宽就使用 `width:100%`、`flex:1` 或等分轨道撑满。张量维度写在角落，维度大不代表单个元素框要大。
- 元素框优先采用内容宽度（如 `max-content`、`fit-content`），用对齐和间距组织成组。矩阵同列、同类操作数可按本组最长标签统一宽度，既保留行列规律，也容纳多位上下标；不要把某个截图的像素宽度定成所有元素的通用尺寸。
- 同一个矩阵内的同类元素格统一字号、宽度和高度，以该矩阵最长公式及上下标的实际尺寸为准；普通行与高亮行共享尺寸，高亮只改颜色或轮廓。跨行共用网格轨道，不能让每行独立按内容缩放。公共矩阵组件与滑窗、转置矩阵等手写布局使用同一约束，不能只修选中行或单个截图。省略号和外侧行名不是元素格，单独留位；省略行的各个点串继承对应数据列轨道。验收比较全部元素格宽高及同列位置，并检查最长下标未裁切。
- 区分元素格、向量与矩阵容器。向量需要容纳代表元素，矩阵需要对齐行列，不能全部压成标量小框；同样不能让一个标量继承旁边矩阵的宽度。并排区域可以等宽，区域内部对象不必铺满。
- 小框收紧后，若父框仍有大片空白，要一起重排父级：独立分支横向并排；串行阶段可用向右箭头连接，过长时分行并保留明确的跨行连接。不能只在巨大空框中摆几个小格，也不能用无关内容填空。
- 收紧过程中保留字号、代表元素、完整变量名和端口净空，不靠缩字、隐藏溢出或删结构达标。尺寸变化后按实际边界重算连线，箭头仍须接到对应小框。
- 验收同时看外框和框内留白：在相同字号与缩放下加宽父容器，内容未变的元素格不应随之等比例膨胀；再换成最长索引与标签，确认文字完整、行列对齐且连线不穿框。没有溢出不等于紧凑，必须截图检查元素文字两侧是否仍有无意义的长条空白。

### 整页布局与宽度预算

按下面的顺序完成排版，缩放倍率和字号在过程中保持不变：

1. **元素格**：宽度 = 实际排版后的文字宽度 + 左右内边距 + 边框。项目默认左右各 8px；重复密集的向量可用各 4–6px。上下标最长项参与测量，不以源码字符数估算公式宽度。
2. **矩阵 / 向量**：一列的宽度取这一列各行内容的最大值，同列共享轨道（如 CSS subgrid）；外框宽度取“各列宽 + 列间距 + 行号栏 + 内边距”与“标题、维度所需宽度”的较大者。标题变长只扩展容器，不拉长元素格。省略号独占窄轨道。
3. **运算组**：依次累加操作数、运算符、间距和连线净空。标量与矩阵可在不同宽度轨道中；两个并行分支按各自内容分配宽度，不强求等宽。四条同级残差路仍保持同排。
4. **模块**：采用能装下最宽必要运算组的宽度，移除原来为了撑满页面留下的固定宽度。串行链可折行，转折有明确方向；独立分支横向组织，短分支的结果靠近真正的汇合点。长说明放旁注或解释面板，避免一句说明决定整张矩阵的宽度。
5. **外层画布**：用收紧后的实际模块边界重新排列阶段、计算高度并布线。某条支路需要专用走线空间时保留净空；无连接用途的大块空白应通过重排消除。不能把串行变成并行，不能为了填空增加重复矩阵。

全页检查包含 Tokenizer、Embedding、残差流、mHC、归一化、Query/KV、压缩、Indexer、Attention、投影、Router、专家及层间交接；同时覆盖首层、复杂层、复用层、末层的 Prefill / Decode 代表模式。要检索公共图元以外的手写格子，而不仅仅检查通用组件。

本项目自动审查可将“只有一个公式的元素框，宽度至少 100px，空余至少 48px，且超过公式宽度两倍”列为候选，逐一消除无意义留白。带中文说明、标题或维度的容器单独检查，不把它们误判成标量；这些阈值仅用于发现问题，不能据此把所有格子硬设为 99px。还要测试父框加宽后元素尺寸不变、最长标签不裁切、矩阵同列对齐，并截图核对整个模块与局部细节。

**错误案例：** 四个 p 元素各被 `1fr` 拉成 120px 的条形；改成内容宽度后，仍把它们摆在原来的 600px 容器中央。正确做法是同时收紧 p 向量容器，说明自然换行，重新分配 p/q 所在分组和相邻 C 分支的宽度，更新真实输出端口。避免把“没有溢出”当成“布局合格”。

### 语义配色与透明层级

本项目使用低饱和浅填充与较深同色导线，文字保持深色。采用八个角色色系，按语义使用：蓝色表示残差与输入，绿色表示数据与激活输出，靛蓝表示学习到的投影参数，琥珀表示缩放 / 路由系数，梅紫表示仿射中间结果，青色表示归一化 / 加权运算结果，玫瑰表示回写权重 q，紫罗兰表示残差混合矩阵 C。局部图例说明具体变量；同一对象在生成端、别名、代理和消费端保持色系一致。

新角色确需区分时扩展配色 token，先定义其含义再选择色相。专家编号与分组边界可另外标识，但不能让同一个输入 Y 在共享专家里呈蓝色、到路由专家就变成橙色。颜色只辅助识别，变量名、端口与形状仍应独立说明结构。

- 白色画布，分组框和已展开矩阵 / 向量的外框均透明；内部真实元素格必须保留明显底色。透明规则只作用于容器，不用继承样式或全局透明选择器抹掉子元素填充。
- 同一矩阵的元素保持一致，选中行通过强调边框 / 轮廓单独标识。
- 导线较深、较粗，容器边框稍浅、较细，但在正常阅读尺度下必须清楚可辨；不能以接近白色的边框制造层级。选择态有独立强调，不能与普通数据线混淆。截图分别核对矩阵外框、元素边框、元素底色和导线，检查蓝、绿、参数色等各类对象。
- 检查透明外框内部的元素、长索引和交叉处，底层导线不能穿过文字。颜色调整不以滤镜、模糊或逐帧效果增加交互开销。

### 框体间距与环形排列

同级框体的实际矩形不得相交，内部元素格、缓存槽位和中心标签也要检查；父子包含关系单独处理。框间保留可见净空，检查对象包括边框、文字和尺寸变化后的边界。

环形布局按卡片矩形验收，而非只看圆心或圆周。例如直径 240、半径 81.6 的圆上放 8 个 72×28 槽位，顶部与斜上槽位的中心纵距只有约 23.9，小于卡片高度，卡片会重叠。可按空间增大半径或收紧卡片尺寸；当前示例采用半径 87.6、约 63.6×21.6 的卡片，最近纵向净空约 4。中心写入标记和底部标题也须避让。省略号只显示符号，不铺背景或伪装成槽位。

浏览器验收时两两比较同级元素的 `getBoundingClientRect()`，横向和纵向的重叠长度都大于 0 即失败；额外核对文字是否越出自身卡片。正常阅读宽度、窄屏和有两位数层号的模式都要截图检查，不能靠提升层级或隐藏裁切遮住重叠。

## 模块解释面板

本项目的结构图与文字解释并存，面板不能替代图中的结构展开。

- 首次点击模块打开右侧面板；面板已打开时，点击其他模块只更新内容，保持打开，直到用户手动关闭。关闭后继续点击模块只改变选择，不自动重开；点击“展示解释”或固定展开才恢复常驻显示。悬停入口可临时预览，结束后仍保持用户的关闭偏好。将选中对象、固定偏好与临时预览分别管理。
- 内容针对当前模块和当前模型、层号、Prefill/Decode 状态，写清模块作用、每个变量的定义与形状、输入来源、内部步骤、公式推导、输出去向和必要的数值例子；不能只换标题或复述图上的缩写。
- 面板与画布分配独立空间，不能覆盖刚点击的框。打开或调整宽度后，确保目标框仍在画布可见区域内，必要时最小幅度平移；不能靠把整图缩到字看不清来避让。窄屏也须保留图文对照，不能直接用遮盖目标的浮层交差。
- 外观简洁、素雅，标题与正文层级清楚，滚动阅读稳定。面板内滚轮只滚动文字，不带动画布；拖动框、连线或画布不能被误判为点击打开面板。
- 验收完整序列：点击 A 打开 → 点击 B 保持打开并换内容 → 手动关闭 → 点击 C 仍关闭 → 点击“展示解释”显示 C；另检查面板打开时目标框不被遮挡。

### 侧栏预览与滑动

本项目及同次维护的 OasisMind 左导航、右解释、来源、文章目录和会话工作栏采用下列规则；复用现有交互控制器，公共规则同时覆盖各入口。

- 左右固定状态独立。收起、等待悬停、临时预览、固定展开有明确转换：入口持续悬停才预览，离开后收回；预览内导航后立即开始收回，固定状态下导航保持展开。关闭、跳转、切换上下文、卸载都取消待触发的悬停，不能稍后又自行弹出。
- 预览呈现同一份真实内容，链接、输入、滚动、树形展开、下拉菜单、切换页签均可用。移动到侧栏及其所属菜单时保持可操作；收回保留输入与滚动位置，不建立只能看的截图或另一份简化界面。
- 入口停留与滑动分开：本项目采用 **500ms 悬停、240ms 缓出滑动、160ms 移出容错**。这些具体数值是项目选择；指针短暂经过不展开，返回侧栏可取消收回，点击固定立即响应。入口固定在页面边缘，动画期间也可操作、可反向，不为文字逐项加延迟。
- 侧栏从对应边缘滑入，使用并排占位；轨道宽度与内容位移使用相同曲线和时长。预览、固定及滑动中间帧均不压住正文或所选框；当前对象必要时做最小平移，保留可读缩放。窄屏改为上下分区或独立触屏入口；触屏不依赖 hover。不能把瞬间出现、仅透明度闪现或覆盖正文的浮层当作滑动实现。
- 键盘可通过入口进入完整内容，Tab 顺序自然；Escape 关闭并归还焦点，收起内容不可被 Tab 命中。点击、键盘入口无需等待鼠标延迟。遵守系统减少动态效果偏好，关闭位移动画仍保留功能。
- 动画由容器负责，内容保持稳定。避免每帧重建全图、重复渲染公式或把侧栏动作传成 Chat 消息状态更新。宽度改变后重新核对可视区域，滑动过程的性能用浏览器测量。

**错误案例：** 鼠标一擦过按钮即弹出浮层；移动到预览内容时提前关闭；点击章节后又被未取消的计时器打开；关掉后隐藏项仍能获得焦点；目录预览盖住正文；展开一边同时改变另一边的固定偏好。验收应逐个复现这些动作，确认都不会发生。

**验收序列：** 左右分别收起 → 快速经过入口 → 持续悬停 → 进入预览并滚动、输入、展开目录或操作下拉 → 点击跳转后保持隐藏 → 固定展开并导航 → 独立关闭另一栏 → 等待中取消 → Escape / Tab → 减少动态效果 → 窄屏。截图覆盖滑动中间帧与完全展开，测量侧栏与正文、画布边界不相交；原先选中的对象仍在可视区域内。测试入口、正文、目录、来源与工作栏，不能仅验左导航。

设计参考：[Fluent 2 Drawer](https://fluent2.microsoft.design/components/web/react/core/drawer/usage) 的并排抽屉及完整内容，[Fluent 2 Motion](https://fluent2.microsoft.design/motion) 的自然缓动与减少动态效果，[Baymard 悬停研究](https://baymard.com/research-articles/dropdown-menu-flickering-issue) 的 300–500ms 防误触区间。参考原则用于本项目取舍，不照搬另一产品的模态遮罩或默认时间。

## 画布外观与阅读

- 本项目采用用户提出的透明大框试验样式：分组大框保留外轮廓，内部背景与画布一致，不铺整片白底；数据小框继续保留语义色。此项是项目样式选择，不要求所有模型图都透明。检查嵌套边界、文字对比度及底层连线，透明不等于允许线穿过文字。
- 变量在框内，维度放标题角落，不采用“第一行一个变量、第二行一个维度”的高大空框。正文与变量在常用阅读尺度下可读，不以反复放大作为正常阅读前提。
- 连线标签按用户要求至少比普通说明字大三个字号档位，使用明确的字号 token 并在同一缩放下比较；本项目现用 20px 与 13px 作为基准。长线箭头端重复变量名；保持透明背景并让线避开字，不靠白底遮线。
- 选择只高亮原有边框，不叠第二层错位框；无关蓝色端口框、缩放点不能常驻。颜色扩展按语义进行，保持同对象在生成端、代理和消费端一致。
- 选中连线改变原路径的颜色，不绘制第二条虚线覆盖；内部透明命中区不得变成可见线。选中框只改变原边框，取消选择后恢复。相同类别的连续线段与箭翼采用统一描边宽度和缩放规则，放大、缩小、选中后都检查，不能把一段屏幕恒宽线接到一段随世界坐标缩放的线。

## 持续可编辑交互

- 结构图内部无需设置阅读/编辑开关：空白区域拖动用于平移，节点拖动用于改位置；无需选中即可拖动完整边缘调整尺寸，选中只突出原边框，不叠加第二个框或八个控制点。端口和边始终可操作。连接端口默认透明并保留命中区，悬停达到延迟后才显示 `+`；连接与重连半径应允许端点靠近后吸附。
- 固定起线点与已连接端点优先响应连线，其余边缘响应缩放，不能让两种操作争抢同一事件。连接点沿边界的 20%、40%、60%、80% 等位置分布。连接点默认完全隐藏，指针停留 0.5 秒后才显示圆形 `+`，移开立即隐藏。
- 新建线只从固定起线点发起；点击 `+` 可锁定起点，拖动时开放式箭头跟随指针。目标采用连续边缘吸附：指针进入任意框边的吸附范围后，松开鼠标就连接，不要求再次点击或命中离散 handle。
- 既有边的两端可按住拖动，沿原边滑动时固定法向位置，只改变边上比例；也允许重连其他框。端点存储为节点 id、边方向和归一化比例，不能存绝对屏幕坐标。历史、保存、恢复均包含该数据。
- 端口中心与可见框边重合，路径端点按实际节点边界计算，不能取大号 handle 命中区的外沿。普通端口和未选中边的端点只在局部 hover 时显示；选中边显示两个端点，线段拖动点仅显示鼠标附近的一个。
- 所有主流程边显式指定 sourceHandle/targetHandle，匿名主端口改为稳定 id；新增连线端口不得通过“第一个 handle”冒充主流程出口。浏览器应直接测量路径首尾与节点边界的间隙。
- 四条完整边缘始终保留透明缩放命中带，鼠标靠近即可显示缩放光标并直接拖动，不要求先选中节点。四角控制宽高，四边控制单轴；选中框不显示八个点，角落提示仅局部 hover 时出现。起线点、连线端点与缩放命中区重叠时优先连线，其余边缘均可缩放。
- 有独立语义且需要人工调整的内部对象使用嵌套 child node；父节点先于子节点注册，子节点位置相对父节点保存，并允许直接连接到其他父框内部的真实 handle。
- 文章宿主是否处于编辑状态，不改变结构图自身的交互规则；两者不得共用同一个 `editing` 状态。
- 连线必须从真实 source handle 拖到真实 target handle。删除连接以边为单位，不能连带删除语义节点。
- 人工位置、尺寸和连接可保存为独立布局覆盖层；自动语义图仍是可恢复的底稿。保存失败必须可见，不得悄悄丢失用户调整。
- 布局覆盖层同时保存连线端点、LaTeX 标签和人工折线控制点。基础语义边重连后不能在恢复时被默认端点覆盖。
- 连线的透明命中带覆盖真实线身，按住即可拖动最近线段；局部控制点只作提示。标签断口处由文字本身接收拖动。主标签、箭头端复述使用同一内容、各自的位置偏好及同一套避让和历史，不能把终端标签设成 `pointer-events:none` 后声称标签可拖。
- 线段拖动以按下时的路径和画布坐标为基准，只应用垂直于线段的鼠标位移；保留命中带内的抓取偏移，不能首帧把线吸到鼠标上。手势中固定被抓线段，不因重新路由切换折点身份；未编辑的远端、连接端点及无关通道保持稳定。端点适配与路径化简必须保持正交：先去除连续重合点，再删除同向共线点，不能把 `[A,B,B,C]` 的两个 B 都删除而生成斜线。测试包含偏离线中心抓取、沿线移动、跨越相邻折点、多帧往返、零位移恢复、缩放、撤销与保存恢复，并逐段检查正交性。
- 撤销、重做监听当前图的活动生命周期，焦点在工具栏、层按钮、侧栏和页面空白时均有效；焦点在输入框或可编辑文字时保留原生文本撤销。一次完整拖动记一条历史，单击选中不创建空操作；卸载后移除监听，不能重复执行。
- 交互回归直接用鼠标命中线身与两类标签，不调用内部处理函数。分别在选中前后、缩放后、焦点离开画布后执行拖动、Ctrl+Z、Ctrl+Y、Ctrl+Shift+Z，再保存恢复。核对真实路径与标签位置变化，不能仅检查光标、按钮启用或数据字段存在。
- 调整尺寸后重新计算端口与边路径；不能只改变外框而让内部端口停在旧位置。
- 画布同时支持空白处拖动与普通滚轮上下平移；缩放保留明确的独立手势或控件，不能把普通滚轮固定为缩放。面板和其他可滚动控件内的滚轮不传给画布。

## 交互性能验收

本项目用户目标是可见反馈不超过 30ms。分别测量整画布平移、单框拖动、滚轮平移、缩放、切层、解释面板首次打开与切换；单框顺畅不能证明整画布顺畅，缩放顺畅也不能证明切层达标。

- 在生产构建、最复杂完整层及面板打开场景实测，记录环境、图规模、首次与重复操作的耗时、P95 和长帧。区分事件处理耗时、下一次可见绘制和完整内容就绪时间，不能只用处理函数执行时间宣称 30ms 达标。
- 平移与缩放不改变图语义，不应逐帧重建全部节点、重排整图或重新渲染全部公式；静态内容与视口变换分离。切层缓存和按需渲染不能留下旧层变量、错位端口或隐藏用户要求的结构。
- 用真实连续拖动、滚轮和连续切层验证，不只测一次点击。截图验收与性能验收都通过才可声明完成；未达标时报告实际测得的路径与指标，不能用“感觉丝滑”或单测绿替代。

## 边路由

- 默认使用分层正交路由，同层对应端口尽量垂直对齐。模块内部的分流、汇合与求和输入线也优先使用直角折线，避免斜线穿越大块空白；转折保留箭头净空。
- 选中边后只在鼠标靠近的正交线段显示局部拖动控制，不把每段控制点同时铺开；拖动水平段只改变该段的纵坐标，拖动竖直段只改变该段的横坐标。端点另用 reconnect 控制拖到新端口，不能把“改路径”和“改连接对象”混成同一种操作。
- 一条边只由一个边组件绘制，不用多个短 `div` 拼折线。
- 自动折线先对除起点、终点及其父容器之外的节点矩形做避障；满足避障、线间净空、端口方向与独立落点的候选，先选转折最少的，再选长度最短的。无合法候选时应调整通道或布局，不能拿穿框路径交付；人工控制点存在后不再擅自改路。
- 自动路由必须使用全图统一的节点外扩安全区与端口法向引出长度。候选通道按外扩后的矩形计算，横向或纵向转折不得落在框边及其安全区内；这是路由器不变量，不为某一条边写坐标特例。
- 箭头属于终点，线段连续到箭头基部；不能出现孤立小线头。
- 使用开放式 `Arrow` marker，不使用填充的 `ArrowClosed`。路由起点先沿 source handle 法向离开节点，终点前再加入与 target handle 法向一致的短引入段：Top 向下、Bottom 向上、Left 向右、Right 向左。不能让线贴着源框边横走，也不能让箭头横着贴到目标上边缘。扇出边使用分开的具名 source handle，使每条边的来源可辨认。
- 给主路、残差、路由和共享旁路预留不同通道。跨多个分组的线沿容器外侧走，不穿过公式和节点。
- 边标签的中心始终在线路上；拖动时投影到最近线段，并将位置存为沿路径总长度的比例。节点移动、重连或折线改变后按新路径还原；拖标签一次只记一条历史。标签不能自由漂到线外，也不能看起来像新节点。
- 长边的变量复述、文字净空及编辑后的保持遵循下节“连线标签避让与动态保持”；字号沿用“画布外观与阅读”。
- 线密度太高时，优先使用合法输入代理或分层总线；不能把不同语义的多条边合成一条无法追踪的线。

### 连线标签避让与动态保持

标签参与整页布局，初始显示和编辑后的结果使用同一套约束。

- **长线入口复述。** 主标签之外，在箭头附近再次写明所传变量，保留层号、分支号和上下标；两处引用同一标签内容，改字时同步更新。优先安排终端标签，再放主标签。目标是内部小框时，可在外层入口前的安全位置复述，并让连线继续指向同名内部对象；不能把入口标签退回远处中段，也不能只在源头命名。
- **全图统一避让。** 按实际渲染的公式宽高（含上下标与内边距）预留净空，同时检查全部框体、其他导线及其他标签。标签中心留在所属路径上，该路径只在文字占据的局部断开描边；其他导线不得穿字。保持透明背景和既定字号，不用白底、提高层级、缩字、删上下标或隐藏标签掩盖碰撞。折点与箭翼也须留出完整空间。
- **先保证可读，再选择路径。** 预留通道时同时考虑线宽和标签宽高；线能通过不代表文字放得下。优先沿现有路径寻找安全位置，无位置时调整自动通道或相关布局，再按最少转折规则择优。保留用户手动路径与标签位置偏好；偏好与净空冲突时先就近避让，无法兼顾则明确提示需要调整，不能静默覆盖人工路径或把重叠当作完成。
- **变化后仍成立。** 拖动或缩放框、改变内部端口、重连、编辑折线、修改标签及切层后，按最新几何与文字尺寸重新规划。移动的框可能挡住无关连线的标签，不能只更新该框直接连接的边。标签位置随路径还原，主标签与终端复述同步；纯画布平移和缩放复用世界坐标布局，不逐帧测量全图公式。
- **编辑状态一致。** 标签沿线拖动、文字编辑、撤销/重做及保存/恢复共用连线数据与历史；工具栏选中态从该数据派生。点击标签不能被画布空白点击取消选择，撤销后仍能继续编辑，恢复后重新执行避让。

**验收序列：** 在首层、复杂层、复用层与末层的 Prefill / Decode 代表模式逐模块扫描；正常阅读宽度与窄屏均检查。先检查默认布局，再拖动源框、目标框及邻近的无关框，改成带更长上下标的标签，执行撤销/重做、保存/恢复。每一步都核对标签—框、标签—真实线段、标签—标签的碰撞，以及终端标签到箭头或外层入口的距离；只检查“存在重复标签”不够。最后截取完整模块与入口局部，确认变量可读、无压线压框、无相互遮挡。自动检测须保留文字断口，不能把不同 SVG 子路径误连成穿字线。

本项目优先复用 `tests/edgeLabelLayout.test.ts` 与 `e2e/edge-label-audit.spec.ts`，按上述交互序列补充缺失覆盖；路由变更同时运行避障、通道间距与交互性能回归。不得为使测试通过而删除终端标注检查、忽略编辑后碰撞或放宽到明显远离入口的距离。

**错误案例：** 标签只避开自身连线，结果被旁边一根线穿过；或 C 的重复标签位于回写框下方远处，实际箭头却在左侧上方。应把标签占用空间纳入公共通道规划，在入口旁放下完整变量，并检查拖框和改字后的同一区域。

### 距离与通道硬约束

- 相邻层之间的净空必须容纳源 handle、箭头与目标 handle，需要转折时再预留正交通道；端口对齐且方向允许时直接连接。若路由器的 offset 为 `o`，需转折的层间净空不得小于 `2o + 箭头长度 + 安全边距`。
- 横向并列的节点之间要留下专用竖向通道。需要跨越下一层的边先进入通道，再向目标转折；不得从相邻节点内部“穿过去”。
- 同一阶段的并行节点尽量让相关 source/target handle 对齐。若无法对齐，转折放在两层之间的空白带，而不是贴着节点边缘回头。安全区必须同时作用于碰撞检测、候选通道和起终点引出段；只给碰撞矩形加 padding、却仍让转折线贴边，仍算失败。
- 长残差必须是一条连续、有箭头的真实边，从原始状态节点直达加法器。不能用颜色相同的短线暗示连接。
- 编辑历史以完整交互为边界：拖动开始前留快照，松手后提交；逐像素变化不得逐条入栈。节点、尺寸、边端点、折线控制点和标签共用同一撤销/重做栈。
- 小框是实际数据源或目标时，handle 放在小框上；禁止把线先接外层大框，再让读者猜它对应哪个内部向量。

布局后必须执行边—节点碰撞检查：沿每条路径采样，排除它自己的 source/target 后，任何采样点进入其他节点内部都算失败。只凭截图肉眼判断不够。

自动布线必须统一规划，而非每条线独立取最短路。手动路径先预留，自动路径逐条预留已占用线段；平行长段须保持通道间距，并检查两两共线重叠。候选通道应覆盖起点、中点和终点附近，不能只保留中点附近候选而丢失起点旁的窄通道。扇出区净空按“源引出段 + 目标引入段 + (分支数 − 1) × 通道间距 + 安全余量”计算，保证各路有空间转折。

### 最少转折与整页布线检查

路径选择顺序为：**满足几何约束 → 转折最少 → 同转折时长度最短**。几何约束包括不穿无关框和文字、不共线重叠、平行线留净空、输入落点分开，以及源端法向出线、目标端正确进入和箭头净空。不能用减少转折的名义取消这些约束。

- 以实际绘制的完整路径计数，包括源端引出与目标端引入段。先移除零长度段、合并同向共线段；保留并拒绝反向折返，不能删掉折返点掩盖尾刺。对齐路径优先零折，L 形优先一折，只有避障或端口方向需要时才增加转折。
- 相向且对齐的端口之间无遮挡时直接连接。两端框外安全区重叠不能强迫直线绕出窄 U 形；安全区约束转折与旁线净空，直连仍需核对无关框、标签及既有线。错误案例：85px 间隙各预留 44px，得到两根相距 3px 的反向竖线，视觉上像乘号旁多出一条粗刺。
- 从框右侧出发且目标在右下方，先向右离开框再向下；若目标要求从左侧进入，保留最后向右的入线段。无填色方形 Σ 可按来线方向选择合法方框边缘落点，不必机械套用矩形端口的三段模板；同时检查其他输入和输出线，避免少了一折却交叉了。
- 检查全页所有公共图元及手写 SVG，覆盖跨模块线、分流、汇合、求和、旁路和跨行连接。逐条核对源框边界、目标边界、转折点与相邻线；同一对象的输入分配不同落点，不靠白底、遮罩或隐藏线段掩盖冲突。
- 自动检查按真实线段比较，不能把标签留白处的两个子路径误连成一条假线。比较共线重叠、平行净空和端点距离；几何检测与截图互补，不能以“未穿框”代替全部布线合格。
- 验收首层、复杂层、复用层与末层的 Prefill / Decode 代表模式，逐模块截图；检查正常阅读尺度及局部箭头细节。公共组件修复后复查所有调用，保留用户人工保存的路径。

**错误案例：** 四个并排输入汇入 Σ，每条机械采用“向下 → 横移 → 再向下”，即使直线或一次转折已能到达不同方框边缘位置，仍多加一个弯；或者只计算中段折点，接上首尾引出段后从两折变成三折。应按完整路径比较合法候选，沿方框边缘分配分离入口，再检查箭翼、线间距和输出方向。不得把不同输入挤进同一点来换取少转折。

## 运算节点

Σ 累加器和超过两个输入的运算节点统一为透明底色、中性深色边框与符号的正方形。颜色仍可用于数据与导线，运算节点本身不填语义色。两输入乘法保留紧凑裸运算符。

入口按来源方向和相对顺序分配到不同边：例如左侧纵排四个输入，首项从上边进入、末项从下边进入，中间两项使用左边不同落点，输出单独从右边离开。逐条检查箭翼、折点、文字及框边净空；普通穿越不得压在边框上，只有真实端口可与框边接触。所有导线、标签和边框都参与碰撞检查，包含大框内部的手绘路径。

来源横向展开、Σ 顶边拥挤而两侧空闲时，将最左、最右输入分别接左、右边，中间输入接分开的顶部落点，输出留在底部。不能机械地把所有输入挤在顶边；重新路由后核对左右入口的实际边界、箭翼、标签与平行通道，不以多绕线换取表面上的分散。

**错误案例：** 纵排四项一律折向 Σ 左侧，造成输入交叉、共线或箭翼挤压；长线变量放在紧贴框边的折点，又被邻线穿字。应先分配各侧入口与输出通道，再规划最少转折路径，并按完整文字边界留出净空。

内部数据框、元素和连线必须可点击选中，选择反馈精确落在命中对象上，解释面板显示当前对象及所属模块的完整说明。内部线提供独立命中区域，不能被装饰层遮挡，也不能借父框选中冒充内部交互。关闭面板后点击只更新选择，显式展示时恢复当前对象；拖动画布和模块仍保持原有手势。验收必须实际点击最内层元素、内部向量、汇合输入线和运算节点，并检查关闭、换选、重新打开的顺序。

至少区分：

- `BinaryOperator`：两个输入、一个输出，用于 `+`、`\times`、`\odot`。
- `MultiInputOperator`：超过两个输入，使用无填色方框与独立入口；Σ 也统一采用该外观。
- `NamedOperator`：Softmax、Top-K、RMSNorm、Concat 等命名操作。
- `TensorBox`、`VectorBox`、`ScalarCell`：只表示数据，不承担运算语义。
- `GroupFrame`：只分组，不代替内部节点接线。

乘号可以位于两条输入线的交点，或使用小型无底色运算节点；不能使用与张量框同尺寸、同视觉权重的矩形。

加法与多项累加统一使用无填色方形 Σ 节点：各操作数分别有输入线进入方框边缘，输出线离开方框边缘后接结果。节点保持正方形、透明底色和中性深色边框。若操作数距离较远，在线旁或输入端保留变量名；“逐元素求和”可写在旁边，但不能替代连接结构。

每条已展示输入线都带朝向 Σ 的箭头，并分配方框边缘上彼此分开的落点；不能全部挤到同一点，也不能只有输出有箭头。输入过多时调整方框与分支间距，不把同构省略项画成 `+ … +` 或无来源短线。

同一分组内的独立分支使用同一行 Grid/Flex，不用自动换行把并行过程排成上下步骤。纵向产品列表汇入求和器时，每个产品行都必须接线，不能只让最后一行向下指向 Σ。内部连接可由组件级 SVG 绘制，不必为每个元素注册 React Flow 节点；坐标由同一布局网格或实测边界推导，检查端点和框边贴合。

**错误案例：紧凑矩阵外套撑满的运算行。** Attention 中 `aᵢ × vᵢ` 的 v 框收紧了，外部运算行仍使用 `1fr` 分配剩余宽度，求和线从包装层边缘起画，造成输入断线和大片留白。应按“系数 + 乘号 + 向量 + 走线通道”确定运算组宽度，将实际向量右边界与求和输入线起点对齐；省略号单独占紧凑行。整体居中或对齐后，输出线与结果框也须保持连接。此规则同时检查 Attention、残差加权与归一化求和。

验收须同时量输入线起点到实际操作数边界、终点到 Σ 方框边缘的距离，并检查运算符与相邻操作数间距。仅检查箭头落在方框边缘上会漏掉源端断线；仅检查小框宽度会漏掉外层运算组的空白。

## LaTeX 渲染

- 公式只通过统一的 KaTeX/LaTeX 组件渲染，不把 TeX 命令当普通字符串显示。
- JSX 静态字符串与 JavaScript 模板字符串的反斜杠规则不同，修改后必须在浏览器核对；页面出现 `times`、`text`、`operatorname`、`boldsymbol` 等裸命令即为失败。
- JSX 静态属性不是 JavaScript 字符串转义：源码写 `tex="\ldots"`、`shape="N\times512"`。只有花括号内的 JavaScript 字符串或模板字符串才写 `"\\ldots"`、`"\\mathbb"`、`"\\times"`。把两种语境混用会在页面出现 `cdots`、`times512`、`operatorname` 等裸文本。验收不能只数 `.katex-error`，还必须扫描页面可见文本。
- 长公式优先拆成多个有数据语义的小框和运算关系，不能靠缩小字号、强制换行或 `overflow:hidden` 塞进一个框。
- 多位上下标使用花括号；矩阵维度、函数名和转置写法在全图保持一致。

## 自动验收

连线局部还须检查箭头与折点的完整轮廓：箭头尺寸不能随选中线宽被额外放大，箭翼要有独立净空；自动路径禁止“越过引入点再沿原线折返”，否则会在箭头反方向留下短尾刺。验收时同时检查端口方向、最后一段直线与相邻通道，不能只检查箭头是否指向目标。

在最复杂模式和至少一个窄屏宽度运行浏览器检查：

1. 比较每个节点的 `scrollWidth/clientWidth`、`scrollHeight/clientHeight`；任何正溢出都失败。
2. 检查所有边都有存在的 source、target、sourceHandle、targetHandle；控制台出现 handle error 即失败。
3. `.katex-error` 数量必须为 0。
4. 扫描可见公式文本；不得出现未渲染的 TeX 命令名。
5. 对每条边做路径采样，确认不与无关节点内部相交；最复杂层和复用层都要检查。
6. 截取最复杂区域，人工确认内部最后一个小框没有被父容器裁切；只检查外层 scroll 尺寸不够。
7. 核对边数量与语义图。例如展示 3 个 head，就应有 9 条 `Q/K/V` 输入边，不能只有 3 条外层总线。
8. 对正常阅读宽度和窄屏分别验收；缩小 viewport 后不能靠整体缩放把错误藏起来。
9. 改变一个标签长度、专家数或 head 展示数，画布高度应自动变化，不需要修改 registry 或 Markdown 常量。
10. 按“模块解释面板”的完整开关序列检查状态、内容与避让，按“交互性能验收”记录实测数据；没有实际浏览器测量时不得声明交互已达标。
