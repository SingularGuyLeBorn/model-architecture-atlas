# 历史反馈与实际断言追踪

本项目历史要求登记在 [scripts/session-requirements.mjs](../../../../scripts/session-requirements.mjs)。目前按原始会话用户消息顺序整理为 96 条独立约束；重复反馈合并但保留来源编号，问答、范围决定和已被替代的要求单独注明。编号不是 JSONL 行号，也不包含模型伪装成用户的目标续跑指令。

使用 [audit-session-requirements.mjs](../../../../scripts/audit-session-requirements.mjs) 只读扫描指定 session，生成本地 `artifacts/session-requirements/audit.json` 和 Markdown 对照。它逐条关联规范、检查文件、实际断言行号及源码哈希；未分类消息必须显式处理。原始会话和账号信息不得提交进仓库。分享 skill 时，这份项目台账不作为其他模型图的通用事实来源。

静态追踪不是通过证明。每个条目分别记录：

- 对应原始反馈及后续修订，不能沿用已经取消的环形窗口等旧方案。
- 具体断言及实际模型、层、模式、入口；不能以文件名或断言总数代替覆盖范围。
- 正常输入的运行结果，以及故意改坏后的检出结果；故障注入与正常检查使用同一检查器。
- 模块与局部截图、实际打开复核的文件；截图生成不等于人工审查通过。
- 仍缺的状态、交互或语义核对。部分覆盖不得标为完成，也不能用一个统一绿色总分掩盖。

新增 `e2e/projection-contracts.spec.ts` 在六个模型第 4 层两种模式逐模块读取公共 `Project` 的真实输入、权重、输出，检查二维乘法形状、代表项和输入输出分色。它不扫描所有手写乘法，符号维度不能自动当成整数；不能将其表述为全站数学验证。注入错尺寸、单列冒充矩阵、缺代表元素、同色输入输出，分别要求原检查器报对应错误。

新增 `e2e/boundary-interaction.spec.ts` 用真实鼠标在 V4.1 的 KV 入口四侧边缘外松手，核对吸附对象、边中点、换边、撤销重做和保存恢复；另查固定起线点的悬停显示、离开隐藏及未选中沿边缩放。算法单测不能替代这些真实手势，也不代表每个内部小框都已具备独立拖动/缩放能力。

首次进入和切层就绪时间、交互事件到 DOM、下一 rAF 分开报告；30ms 交互反馈不能套成完整加载预算。历史 5ms 极限诉求保留为单独测量目标，后续明确的 30ms 验收不能伪报成 5ms 已达成。
