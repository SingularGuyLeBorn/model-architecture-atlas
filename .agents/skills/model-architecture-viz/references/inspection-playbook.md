# 检查方法与覆盖边界

## 不是纯看，也不是纯脚本

四层检查相互补充：

| 层次 | 能查什么 | 不能代替什么 |
| --- | --- | --- |
| 数据与语义单测 | 形状、来源层、窗口行号、分数→ID→取行、模式分支、拼接映射 | 论文事实核对、最终浏览器排版 |
| 浏览器 DOM 与几何检查 | 实际尺寸、包含关系、颜色、端口、边路径、标签碰撞、状态切换 | 是否好读、留白是否必要、讲解是否连贯 |
| 截图人工复核 | 目标是否截对、文字密度、阅读顺序、分组、真实视觉留白与歧义 | 未显示区域、动态状态、精确性能 |
| 真实交互与性能测量 | 平移、缩放、拖框、拖线、撤销保存、输入后的反馈 | 全设备性能保证、显示器实际呈现时间 |

自动检查最擅长抓重复性错误；人工检查负责理解图。语义核对先于几何美化：一张不溢出的图仍可能把 G 来源连错。反例库是人工审查的提示清单，不是自动判图模型。

## 现有测试怎么选

### 每条反馈都要有可执行检查

`e2e/head-flow.spec.ts` 对代表 Head 的取行、计算和写回检查：按 Head ID 验证对应连接，检查实际 SVG 首尾与变量边中点、路径穿过无关张量框、Q/K 原符号及解析错误。运行 `pnpm exec playwright test e2e/head-flow.spec.ts`，可用 `ATLAS_TEST_URL` 指定生产预览地址。模块与分支截图保存在该次测试输出目录；脚本通过后仍需打开图片核对阅读顺序、索引及连线歧义。

不能只把用户反馈记成文字规范。对可量化要求，必须登记“规则 → 检查入口 → 故障样例 → 覆盖状态 → 结果”，新组件复用检查器。无法完全量化的语义、阅读顺序与留白，也须有结构约束和截图索引，再人工复核；不得声称脚本能替代所有视觉判断。

连线审查最低要求：

| 用户要求 | 自动检查 |
| --- | --- |
| 不穿无关大框及小框 | 实际 SVG 全路径与分组、张量、说明文字相交；仅豁免包含该端点的所属容器，不能豁免整个画面 |
| 不重叠、不混成一条线 | 所有不同逻辑边两两比较平行线段的共线长度；共享源不等于允许共线 |
| 相交尽可能少 | 统计全路网正交交叉，不只检查几根残差；零交叉是可达到时的验收门槛。不能拿更短路径抵消可避免的交叉 |
| 少折返，选合适出入边 | 检查逆向重走、窄 U、相邻模块折数；对争议端口比较四侧候选的穿框与交叉，不默认上进下出 |
| 真变量端口、非角落 | 比对端点与真实数据框端口；同边等分，禁止把分组标题当变量 |
| 箭头与整线高亮 | 检查唯一终点箭头，点击中段和交叉附近时整条逻辑边同一选中身份 |
| 内部小框可点 | 真实点击元素、矩阵标题；检查本对象选中且父节点没有连带选中 |
| 切层、保存、性能 | 全层两种模式检查、人工折点保留、保存恢复与撤销重做；生产构建单独测交互延迟 |

`e2e/mimo-wire-audit.spec.ts` 检查 MiMo 全层两种模式的完整外部路网，断言所有模块和边已经挂载，避免虚拟化造成“没渲染所以零碰撞”。代表层再逐模块放大检查文字、端口与点击，并保存模块图和每个模块的上下文图。故意注入穿框、重叠、交叉、原路折返及错端口，必须分别报错；正常图零报错不足以证明检查器有效。

同一脚本的 DeepSeek 用例专门检查 V3、R1、V3.1、V3.2 第 1、4、61 层两种模式的两条残差旁路。来源与终点在大框内部时，连线必须避开同一大框内的其他张量；不能把源模块整体当成免检区。RMSNorm 上方输入的残差旁路从左侧引出，下方分子行不是这条旁路的通道。修改共享模板后，必须检查全部调用模型，不能用 MiMo 通过代表 DeepSeek 通过。

避交叉不能以紧贴平行线为代价。`e2e/route-separation.spec.ts` 另检查实际平行段间距，发现不满足时必须调整通道，不能放宽间距断言。几何评分同时惩罚穿框、重叠、交叉和绕行，候选搜索与模板端口选择共同决定结果。

`tests/architectureBoundary.test.ts` 对长导线避交叉、四侧入口穿框差异、非角落端点和折返建立回归。候选搜索须包括既有导线端部外侧的通道；只枚举平行偏移会漏掉本来可避开的交叉。自动尺寸测量收敛后必须按完整通道优先级重新规划，临时旧路线不能先占道；平移缩放仍复用同一几何缓存，人工折点不被自动规划覆盖。

这里的“全路网”指模块之间的逻辑边。模块内部取行与求和线另由 `model-expansion`、`sum-source-attachment` 等检查；不能把外部路网通过说成所有内部线也已全量通过。四侧对照回归不是任意图的全局最优证明。人工布局也不在默认布局零交叉承诺内，应单独检查且不得静默删除用户折点。

下表是仓库已有入口，不代表它们本次全部执行或全部通过。测试名不是覆盖证明；运行前阅读当前断言，旧标题也不能覆盖新确认的规则。新增规则应落在相关断言，而不是只改测试名字。

`content-width-audit` 的现有启发式只筛“单公式、没有其他说明、明显宽于内容”的一部分框。它不会自动识别整个模块是否空旷，也不会把含文字的所有大框都列出。没有命中不代表全部紧凑。

`content-bounds` 在第 3、15、29 层的代表模式及宽窄屏检查选行、mHC 与压缩器：从 MathML 实际公式、向量框、元素格和选区轮廓向上逐级比较边框/裁切祖先，报告对象、祖先与越界方向；不把画布视口外的正常内容误报成数据溢出。它另测 mHC 等号等裸运算符到左右框的净空，检查乘积向量外框。检查器会故意收窄并裁切祖先，确认能够报错，再恢复 DOM；不能只用正常页面的零报错证明检查器有效。运行 `pnpm exec playwright test e2e/content-bounds.spec.ts`，先完成构建。它不扫描所有层，也不判定数学语义；新组件须补场景，完整模块与局部截图仍要打开复核。

`candidate-score-caption` 比较说明与框的上下边界、框内文本、公式之外的额外高度，并覆盖多个 Reindex 层。这比只检查“本层分数”四个字存在更接近用户要求，但仍需看截图。

`semantic-palette` 在真实逐层页面扫描压缩器、mHC、Attention、Engram 和 KV 拼接的数据公式所在元素，不把图例或透明容器计入色数；输出已定义/实际使用色系及逐模块清单，并核对压缩生成、暂存、消费与量化 scale 的连续颜色。`color-identity` 另追踪 Full、Reuse、Reindex 与 SWA-only 的缓存来源色，比较选区加深、追加不换色、混合 K/V 及 Value 消费。颜色数达标仍需打开模块截图，检查相邻色的辨识度。

用户要求“每一层检查”时，运行 `e2e/all-layer-colors.spec.ts`：实际切换 40 层 × Prefill/Decode，fitView 后断言所有细节已挂载，再读取真实元素填充；检查局部/全局来源、Indexer 分数单行与矩阵、专家结果及选区。省略号不是数据元素，不纳入填色断言。不存在于该模式的角色可跳过，但必须存在的模块不能静默跳过。输出逐状态的节点数、断言数与异常，不以抽查代表层冒充全层检查。

现有加深填充断言锁定当前组件的具体样式，不代表规范只允许深色。选中可用同色加深或琥珀，两种可并存；组件采用琥珀时同步更新该组选区的期望，并检查来源可追踪、与真实权重可区分。不能把合法琥珀高亮误报为身份冲突，也不能仅因用了琥珀就默认语义正确。

选区检查同时读取元素填充和自身边框，要求同色系配套；旧测试若要求“琥珀底仍保留来源色描边”，应改成配套色断言，并用名称、行号和来源标签检查可追踪性。外围虚线单独测量四侧净空，计入线宽与轮廓偏移，复核邻行间距及父框裁切；普通/选中格仍保持同尺寸。正间距只是自动检查底线，正常阅读尺度还须看得出空隙。具体规则见配色契约。

`e2e/selection-style.spec.ts` 在逐层入口检查 Engram 查表、全局选行、Prefill/Decode 的 SWA 与 mHC 回写：读取元素实际填充及四侧边框，与配套色板比较；把浏览器坐标还原为画布坐标，测虚线内沿到元素、行名和省略号的净空，检查邻行碰撞及祖先裁切。当前组件预留 5px，检查底线为 3px（另留亚像素容差），不是把所有字号的通用标准固定为这个数。检查器会临时制造异色边框、零净空，确认分别报错，再恢复 DOM。结果附在浏览器报告中，截图存入 `artifacts/selection-style/`。

局部回归在完成构建后运行：`pnpm exec playwright test e2e/selection-style.spec.ts e2e/selected-matrix-size.spec.ts`。后者专查普通/选中行的元素宽高、列对齐与溢出；不能因增加净空就放宽等宽断言。前者覆盖公共行组件及两类 SWA 虚线，不是全页面所有手写框的通用扫描器，也不判定数学含义。新增手写选区时补充选择器与场景，不能把未测组件算作通过。颜色全层回归仍另跑 `all-layer-colors`，截图仍需人工查看。

`scripts/scan-all-layer-colors.mjs` 输出全层公式与实际颜色清单；`scripts/audit-layer-colors.mjs` 逐模块定位、截图并列出同公式异色线索。清单与线索不是自动语义判定：作用域同名、合法变换和选区加深均需人工区分。最终汇报分别列出自动检查的层/模式，以及亲自打开的截图变体；80 个状态通过不能表述为人工逐张看过全部模块，也不能证明其他章节已检查。

`interaction-budget` 测输入事件到 DOM 更新及其后下一 rAF 的反馈代理，记录 P95、最大值和样本数。不能只报 DOM 耗时，也不能把下一 rAF 说成显示器实际呈现。帧间隔和反馈延迟分开报告。

## 每次修图的执行顺序

1. **固定范围。** 写明用户要求的入口、模型、层、模式、模块和不改项。查原始模型资料确认数据流，再定位公共组件和手写同类实现。
2. **锁定反例。** 从反例库选对应类别，指出截图哪一处错；不要以整图全部错误为前提。先写能暴露该问题的断言或测量。
3. **按依赖选测试。** 改公式选语义/组件测试；改布局选包含、端口、路由；改公共色板查生成与消费两端；改交互补撤销保存；改导出补离线回读。
4. **运行并保留结果。** 相关类型检查、单测、构建及浏览器回归按改动风险执行。文档整理只检查文档与资产，不假装重新验收了应用。保持已有本地服务，不为截图随意停服。
5. **定位后截图。** 等实际目标内容挂载、字体就绪，核对模块身份和边界在视口内，再截完整模块与局部。自动滚动/变换画布后重新取坐标；文件名正确不代表取景正确。
6. **实际打开。** 查看每张交付截图，先认目标，再看边界、公式、留白、颜色、源端和消费端。像素不可读时换局部截图，不能假装已审查微小文字。
7. **复查动态状态。** 使用真实输入拖框、拖线、缩放、改标签、撤销/重做和保存恢复。性能测试使用生产构建单独运行，避免并发重任务污染结果。
8. **分层汇报。** 说明通过项、未运行项和失败项。只有用户明确要求发布才部署；本地修改、提交与线上发布是三件不同的事。

## 两个已经暴露过的验收陷阱

### 截图错位，DOM 断言却通过

此前“本层分数”修复中，第一次输出图未覆盖预期过滤模块。定位与尺寸断言并未证明最终图片里的对象就是目标；人工打开后发现并重新截取。后续应把目标身份、viewport 包含与截图 clip 放在同一验收步骤，仍保留最后的人看图。

### 局部通过，整组路由仍失败

整理本册之前的工作记录中，`edge-label-audit` 的终端标签距离及编辑后布局检查仍有失败，基线也出现失败。基线复现只能说明不能直接归因于本次修改，不能把失败改报通过，更不能放宽断言掩盖问题。

本册是历史检查经验，不是当前测试状态看板。本次整理没有重跑该组；今后修路由时应重新运行并记录实际结果。只改 skill 的任务也不授权顺手修改整个路由器。

## 证据记录最少包含什么

| 字段 | 内容 |
| --- | --- |
| 范围 | 问题编号、修改组件、同类调用范围 |
| 版本与入口 | 提交或工作树状态、实际 URL、是否本地、是否发布 |
| 图状态 | 模型、层号、Prefill/Decode、当前 t/示例参数、模块 ID |
| 显示条件 | viewport、缩放、面板开关、自动或人工保存布局 |
| 自动结果 | 运行命令、实际退出状态、关键断言/测量、未覆盖项 |
| 截图 | 全模块和局部文件、人工是否打开、仍有的问题 |
| 动态结果 | 做过的真实操作、几何恢复、性能口径与数值 |

不应只写“检查通过”“已截图”“已优化”。检查通过的对象应具体到一种规则、一个入口和一组模式。

## 维护这份反例库

在仓库根目录运行：

```powershell
node .agents/skills/model-architecture-viz/scripts/validate_casebook.mjs
```

脚本检查：18个类别编号、子案例编号唯一性、案例索引、Markdown本地文件引用、图片登记/使用关系、PNG签名/尺寸/字节哈希。在原仓库中还检查提到的测试文件路径；独立分享包明确跳过这项，不要求附带整套应用。图片来源写在 `references/counterexample-assets.json`；当前采用原始附件和已有局部修复截图的逐字节副本。

**这个脚本不是架构图审查器。** 它不能判定留白是否合理、公式是否正确，也不能确认测试中的断言足够。更新后要打开反例册，检查图注是否准确、原图是否清楚，不能把资产校验绿当作视觉验收绿。
