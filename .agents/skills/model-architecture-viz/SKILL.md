# 模型架构可视化组件

目标是让读者沿着线看懂张量如何拆分、进入分支、执行运算、重新聚合。图必须先是结构，公式只标注结构。

## 开工前

1. 阅读目标文章、现有 composition 和所依据的模型资料，写出从输入到输出的语义数据流。
2. 将对象分为：张量/向量/元素、参数、运算、分支、聚合、缓存、残差。不能确定来源与去向的线不画。
3. 对模型特有的 Compressor、Indexer、缓存复用、Top-K 等机制，先核对论文、官方代码或配置。禁止为了补图自行发明中间概念、形状和权重。
4. 阅读 [结构语义契约](references/structure-semantics.md)。使用 React Flow、HTML/CSS 或修改现有 composition 时，再读 [React Flow 与自适应布局](references/react-flow-layout.md)。

## 核心原则

- 大框可表示矩阵；内部小框可表示行向量、列向量或切片。需要解释元素运算，或空间宽裕、能更清楚呈现索引规律时，用代表性元素小格展开向量，保留省略号；窄处保留向量级结构。行向量展开优先参照用户确认的[优秀案例](references/structure-semantics.md#优秀案例行向量组成的矩阵)。
- **并行按横向排，串行才向下接。** 同一步骤的独立分支放在同一分组框内左右并排，结果对齐后再汇合；不能把两个无依赖的过程上下堆叠成假串行。四条平等的残差路保持同排。详见[并行、汇合与整体排版](references/structure-semantics.md#并行汇合与整体排版)。
- **求和必须有连线和圆形 Σ 节点。** 每个已展示的被加项分别接入，输出线连到结果框；“逐元素求和”只是节点旁的补充，不能用孤立符号或一句话代替汇合结构。
- 能用嵌套框表达的组成关系，不写成一行拼接公式。矩阵用大框，代表行或列用内部向量框，向量用横向元素格；保留首、次、省略号和末项即可。例如 `Q_l=[Q_{l,1};\ldots;Q_{l,H}]` 必须改成“左侧整体矩阵 = 右侧含多个 head 向量块的大框”。
- 允许“变量 =”后换行展示结构，也允许下一行对齐等号继续展开同一对象。行向量用横条，多个行向量纵排；列向量用竖条，多个列向量横排。只涉及行选择时止于行向量，不必拆成元素。选择结果优先在原矩阵直接高亮，不能再复制同构矩阵。
- 框按信息量收紧，不能用大片留白模拟矩阵真实长宽比。一次投影尽量在同一排完成“输入 × 权重 = 输出”；变量与维度放在数据框标题内，禁止框外重复写 `=Q=`。两级 Query 投影必须保留完整的升维结果矩阵 `\widetilde Q_l`，再高亮第 `t` 行并横向分成 Head 向量块；不能把整个矩阵直接等同于单个 token 的向量。
- Router 投影同样展开：`Y_l` 画成多条行向量，`W_l^R` 画成专家对应的列向量，一排组成“输入 × 参数 = 得分矩阵”；下方在完整得分矩阵里高亮 Top-K。
- 自动连线同时避让框体和其他连线。并行分支分配独立折线通道，按分支数计算净空；不能让多条线共用长段，也不能靠逐条手调解决默认布局问题。保留用户手动调整的路径。
- 矩阵乘法也优先画结构：展示一条代表输入行、参数矩阵的代表列和一条输出行，并让输出元素与“行乘列”对应。只展开当前运算需要的轴和代表元素，不能用完整公式代替结构，也不能把无关维度全部铺满。
- 内部元素格继承所属数据对象的色系；源对象、代理、连线和消费端保持一致。对象类别增多时扩展有语义的配色并给图例，不限于蓝、绿、琥珀三色；选择高亮与对象本色分开，不能在乘法处无故换色。
- **严禁用代码操作展示选择。** `G[I,:]`、`X[r:t,:]`、数组切片、伪代码和孤立的 `window(128)` 都不能代替结构。必须展开到被选择的语义单元并直接高亮：取行就画行向量框与外侧行号，取列才画列标，取元素才画元素格。矩阵过大时画首、次、末与省略号，但至少展示实际被选中的代表项。
- 任何有独立语义的数据对象都能拥有端口。边可以直接连接内部的 `Q_{l,1}`、`K_{l,1}`、`V_{l,1}`、专家输出向量或分数框，不能强迫所有边挂到外层大框中心。
- 内部小框用于展开大框的结构时，默认不在小框之间铺设 React Flow 连线；同一模块的内部关系靠矩阵嵌套、对齐和运算符表达。只有确实需要跨模块追踪单个对象时才从内部端口出线，普通主数据流只连接外层模块。
- 内部小框若需要移动、缩放、改连线，就必须实现为真正的嵌套子节点；不能把静态 `div` 加上拖动样式冒充节点。父框只承担分组和背景，子节点保留独立位置、尺寸与端口。
- `+`、`\times`、`\odot`、Concat、Top-K、Softmax 是运算节点或连接关系，不是普通数据框。孤立乘号不能套一个和张量相同的方框。
- 公式统一用 KaTeX/LaTeX。多位下标必须写成 `Q_{64}`；标准函数写成 `\operatorname{RMSNorm}`、`\operatorname{softmax}`。
- 符号必须同时表达层、分支和粒度：第 `l` 层第 `h` 个 head 的整段 Query 矩阵写 `Q_{l,h}`，第 `t` 个 token 的行向量写小写粗体 `\mathbf q_{l,h,t}`。不能把不同层都写成无层号的 `Q_1/Q_2`，也不能用大写矩阵符号冒充单个向量。
- 新符号第一次出现时必须交代来源、类型、形状、输入和输出。层内变量始终带层号，例如第 3 层写 `X_3`，不能中途退化成含义不明的 `X`。参数矩阵要与数据矩阵分框，并说明它把哪一维映射到哪一维。
- `Compressor`、`Indexer`、`Attention`、`MoE` 只是阶段标题，不能成为内容。框内必须继续展开关键输入、权重、运算、缓存写入/读取和输出结构。
- 决定模型区别于普通 Transformer 的核心机制必须占据主视觉区，不能缩成角落里的缓存备注。共享结果在哪里生成、哪些层复用、最终在哪里被消费，都要能沿箭头追踪。
- 矩阵行列、向量元素和重复分支，通常至少明确展示第 1 项、第 2 项和最后一项，省略号不计入三项。不能只画首尾，否则看不出上下标变化规律；高亮当前项时也保留前两项。若对象总共只有两项，则完整展示两项，不虚构第三项。已画分支保留完整输入、过程和输出。
- 长距离扇出容易交叉时，可以在每个分支顶部放同色、同名的输入代理框，例如第 `l` 层每个专家顶部各放一个蓝色 `Y_l`。代理表示同一个上游张量，不得伪装成新结果。
- 节点与画布高度由内容测量和布局结果推导。禁止反复修改总高度、节点高度和 Markdown `aspect` 来避免裁切。
- 同级数据框不得互相重叠，包括环形缓存的相邻槽位及中心标记；父框包含子框是结构关系。按实际矩形边界检查间距，环上中心点分开不等于卡片分开。详见[框体间距与环形排列](references/react-flow-layout.md#框体间距与环形排列)。
- 鼠标悬停任意框边即可显示缩放光标并直接按住调整尺寸，不要求先选中或命中某个缩放小点；四边控制单轴，四角同时控制宽高。选中框不展示八个点，角落提示只在局部 hover 时出现，边缘命中区始终可用。固定起线点和已连接端点优先处理连线，其余边缘用于缩放。
- 连线标签允许编辑 LaTeX 并沿线拖动，鼠标偏离时投影回最近线段，不能拖到线外。位置按沿路径的相对距离保存，路径变化后仍在线上；位置与标签、端点、折线共同进入保存和撤销历史。
- 框选中后须有清楚的高亮边框，与未选中状态可辨认；不显示八个缩放点，边缘缩放照常可用。
- 箭头使用空心开放箭头，不用实心三角。目标端口在上边时，最后一段必须从上向下垂直进入；即使上一段紧贴节点上沿，也必须保留一小段明确的向下引入线。源端也必须先沿端口法向离开节点再转弯。一个模块向多个下游分流时使用位置分开的具名 source handle，不能让多条边共用一个出口后贴着框边横走。
- 层间距离必须至少容纳端口、箭头和一次正交转折。自动路由使用统一的端口引出长度与节点外扩安全区；主路、残差、缓存、Router 分配线使用独立通道。线不得穿过无关节点、公式或标签，横向转折也不得贴着任何框边。禁止靠逐条手调坐标修复系统性贴边。
- 左侧结构图只保留必要中文；优先呈现结构、变量、维度和连接，不把正文公式重新堆一遍。

## 项目落点

- 本仓库是独立 React 项目：公共图元放 `src/components/`，通用结构与章节模板放 `src/templates/`，V4.1 完整层图放 `src/compositions/`。不依赖原博客的 composition 注册工具或 Markdown 嵌入服务。
- 新模型先在 `src/data/` 固定官方配置和来源版本，再复用模板；不能复制完整 composition 后只改模型名和几个维度。
- 章节阅读顺序不等于数据依赖。跨阶段连线必须显式声明来源、目标和变量；Query 与 KV、共享专家与 Router、残差混合与输出广播等独立计算不得被默认串成链。
- 概览用来导航，机制图负责展开；在界面和文档中明确两者，不把只有标题的框称为完整结构。
- 语义图、布局和渲染分层：先定义对象与边，再测量和布局，最后渲染。不要把大量坐标散落在 JSX 分支中。
- 修改正在预览的组件时保持现有开发服务运行；通过热更新验收，不为截图随意停止服务。
- 结构图自身不必区分阅读/编辑模式：平移、缩放、拖动节点、拉伸尺寸、从真实端口增加连接、选择并删除连接可以始终可用。文章宿主的阅读/编辑状态与结构图交互是两套独立状态，不得混为一谈。提供显式保存与恢复自动布局，不能让人工微调破坏默认语义图。
- 缩放控制、起线点、落线位置分开：边缘始终可直接缩放，选中节点不显示八个点；新建连线只从固定起线点发起，悬停 0.5 秒显示 `+`。拖至目标框任意边缘附近，松开鼠标即吸附，无需再次点击或精确命中小点。既有边的箭头与起点可按住拖动：上/下边沿水平方向滑动，左/右边沿垂直方向滑动，也可改连其他框。位置按“边 + 边上比例”保存，移动、缩放、撤销和恢复后仍准确。
- 普通端口和未选中连线的端点默认不可见，只在局部 hover 时显示。选中连线只显示两个连接端点；折线段控制点仅在鼠标靠近对应线段时出现，不能整条线铺满控制点。端口中心和实际路径端点必须落在可见框边，禁止停在端口命中区的外沿留下断口。
- 主流程每条边显式指定稳定的 source/target handle id。固定起线点与主流程端口分开，禁止让缺省端口回落到节点中第一个 handle，导致底部出线跑到左上角。
- 所有人工编辑进入同一历史栈：移动、缩放、增删或重连边、逐段改折线、修改标签均支持 `Ctrl+Z` 撤销与 `Ctrl+Y` 重做；一次连续拖动只记录为一个动作。

## 交付门槛

必须实际打开文章检查最复杂模式，并验证：

- 所有可见端口都接到正确对象；没有断线、短线头、反向箭头或悬空标签。
- 正常阅读宽度和窄屏下没有裁切、横向溢出、公式溢出或容器遮挡。
- 非必要连线不交叉；同一 head 的 `Q_h/K_h/V_h` 直达该 head 的对应入口。
- 所有取行、取列、滑窗和 Top-K 都展开到对应语义粒度并有外侧索引与高亮区域；取行无需展示每个元素或无关列标，不得只剩索引公式或代码切片。
- 每个权重与中间张量首次出现时都有形状和职责；共享缓存与层本地缓存的写入者、复用者和使用点可沿线追踪。
- 残差两路都有箭头进入加法器，加法器输出进入下一状态；状态框写明等式。
- 同时截取整个模块与局部展开：并行分支同排、各项实际接入圆形 Σ、矩阵行列未被摊平、长分支旁的空间已合理分配。局部小框齐整不能代替整体排版合格。
- Router 的选择、分数、专家输入、专家输出、逐路加权、求和是不同结构阶段。
- 浏览器控制台没有 React Flow 端口错误，KaTeX 没有解析错误；相关 lint、测试和构建通过。
